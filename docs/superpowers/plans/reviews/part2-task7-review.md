## What I checked and found right

1. **Driver never asks for a frame.** `canvas/RegionNamesDriver.tsx` imports nothing from `state/invalidate` and does not take `invalidate` from `useThree`. Its only side effects are `el.style`/`classList` writes and `setNamesPlacer`. Traced: `place` (L148-276), the two effects (L280-286), `useFrame(place)` (L288).
2. **No layout read per frame.** No `getBoundingClientRect`, `offsetWidth`, `getComputedStyle` in the driver. Size comes from `get().size`, the stage top from a module value, chrome rectangles from constants, text widths from a 2D canvas `measureText` (cached per name, not layout). The one `getComputedStyle` is in `overlays/RegionNames.tsx:31`, in the mount effect (once per mount or toggle on), not per frame. `isNarrow()` at L240 is `matchMedia(...).matches` on a cached list: not a layout read, and only on a placing frame (Minor M3).
3. **Early return is complete for what placement reads.** Read by `place`: layer, world, camera x/y/zoom, canvas width/height, `sliderT`, `insetCurrent`, `input.stop/focus/selected/dimmed/insetLeft/bottomCover`, `namesOn`, stage top, widths version. All 18 are in `Basis` (L94-113, compared L163-182). Not in the basis and why that is fine: dpr (nothing is in device px), phone (`isNarrow()` can only change with the window width, which is in the basis), cover zoom and album open (derived from `zoom`, `height`, `focus`, `insetLeft`), camera frustum (`viewBounds` reads `left/right/top/bottom`, which change only with size), `positionsRef` for the picked album (moves only with `sliderT`), font ready (the version). A hover frame changes none of them: the compare is by field, not by `input` identity.
4. **Cost of an early-return frame:** one `Map` lookup, two `getState()`, 18 compares, no allocation, no DOM touch. Agrees with the report.
5. **DOM writes are skipped when unchanged** (`show` L47-72, `hide` L74-80, `Written` per element in a `WeakMap`, which also resets correctly when the toggle recreates the elements).
6. **Same-frame placement.** `useFrame` callbacks run before the draw in the same animation frame, and the driver is mounted after `CameraRig`, `CameraTween`, `FocusFramer`, `MorphDriver` and `AlbumField` (`canvas/Scene.tsx`), so pan, zoom, pinch, the opening glide and the morph are placed from the camera and slider value that frame draws. One exception, M1.
7. **Rules.** `aria-hidden="true"` on the layer; `pointer-events: none` on layer and names; no listener except `document.fonts` `loadingdone`; `albumOpen = focus !== null || insetLeft > 0` (L208) and `namesShown(coverPx, albumOpen)` with `NAMES_BAND_PX = 13` (below the 16 px cover fade start); `.map-pane.is-dimmed .rn-layer { display: none }`; phone cap is `NAMES_MAX_PHONE = 4` inside `layoutNames`; `PICK_CLEAR_PX = 22` (L21, L247).
8. **Halo is applied per name as decided.** `--h` is written on `.rn` (L63-67); `--rn-ink`, `--rn-ink-far` and both shadow lists are declared on `.rn` too, so their `var(--h)` resolves on the element that carries the value and `b` inherits the resolved lists. `-webkit-text-stroke` and `text-shadow` on `.rn b` equal the plan's values term for term.

## Findings

### Important

**I1. First-load chunk grew 78 bytes: `rawToWorld` is now kept in the router + MapStage chunk.** `canvas/RegionNamesDriver.tsx:11` imports `rawToWorld` from `../data`. `data.ts` lives in the first-load chunk because `MapStage.tsx:15` imports `buildMapData` from it. Before this commit nothing outside tests imported `rawToWorld` (`git grep rawToWorld 85526bfe~1`: a definition and two comments), so it was tree-shaken. Now the chunk carries
`"rawToWorld",0,function(e,t,r){return[(t-e.tx.cx)*e.tx.s,(r-e.tx.cy)*e.tx.s]}` (found in `.next/static/chunks/1horyzljx9xdf.js` of the implementer's build; 77 characters plus a separator = the reported +78 raw, +31 gzip). This is the unexplained +0.03 KB; the report's guess (the lazy chunk list) is wrong: the list still has two files.
Fix: do not import it from the first-load module. Either inline the two multiplications in the driver's `useMemo` (L131: `const wx = (label.x - data.tx.cx) * data.tx.s; const wy = (label.y - data.tx.cy) * data.tx.s;`) or move `rawToWorld` to a lazy-only module (`state/projection.ts`) and re-point its test. Then re-measure: expect 191.21 KB and the Task 6 chunk bytes. The same trap applies to any later task that imports a so-far-unused export of `data.ts`, `lib/media.ts`, `lib/types.ts`, `lib/store.ts`: worth a line in RULES.md.

**I2. The departure has a stale-closure hole when the theme arrives after the map has mounted.** The theme is loaded separately (`MapStage.tsx:173` `useThemeLoad`), so `MusicMap` can mount with `theme = null`: the driver mounts, registers the placer, and its `world` is null. When the theme arrives, `RegionNames` (React DOM root) and the driver (the R3F root) re-render in two different roots. `RegionNames`' effect calls `placeNamesNow()` (`overlays/RegionNames.tsx:34`), which runs `placeRef.current`, and that ref is only updated in the driver's own passive effect (`RegionNamesDriver.tsx:280-282`). If the DOM root's effects flush first, the old closure runs with `world === null`, hits L152-155 and returns; `placeNamesNow` still returns true, so no frame is asked for and nothing places the names. They then appear only on the next drawn frame. Today that frame always comes (the theme's arrival mounts `GasField` and recolours stars, both of which invalidate), so I expect no visible bug, but the names' first appearance now depends on an unrelated component redrawing, and the plan's original `requestRender()` did not. I could not run it to see which root flushes first.
Fix (either, both cheap, neither draws a frame): (a) in the driver add `useEffect(() => { place(); }, [world]);` after L282, so the driver places itself when its label set changes; or (b) make the placer report whether it could place (`return false` at L152-155), have `placeNamesNow` return that, and let `RegionNames` fall back to `requestRender()`. Add the unit test in "Tests" below.

**I3. The late font path is untested, and it is the part of the departure most likely to rot.** jsdom has no `document.fonts`, so `RegionNames.tsx:35-46` never runs in the 10 tests. By reading, the path is right: widths measured before the face arrives are the fallback's (metric-matched, so close); `loadingdone` clears the cache and bumps the version, the placer runs with a changed basis, names are re-measured and re-placed with no canvas frame; the listener is added in the same synchronous effect as the first placement, so the event cannot be missed; a face that fails to load leaves fallback widths with fallback glyphs, which is consistent. What can go wrong and is not pinned: the `fontfaces` filter (L40-41), the listener's removal on toggle off, and a browser whose event has no `fontfaces` (handled: it then re-places).
Fix: one unit test with a stub `document.fonts` (an `EventTarget`): dispatch `loadingdone` with `fontfaces: [{ family: '<the layer family>' }]` and expect `nameWidthsVersion()` +1, the placer called once more, `invalidate` not called; dispatch with an unrelated family and expect no change; switch names off, dispatch, expect no call. Plus the e2e case in the Task 9 list.

**I4. During a slider morph the names repaint their shadows every frame; the full version is untimed and a no-visual-change cure exists.** What changes per frame:
- Pan, pinch pan, opening glide: `transform` only. Each `.rn` has `will-change: transform`, so it is its own compositor layer and the 9-layer shadow and the stroke are not repainted. This is the cheap case. Cost per placing frame: up to 17 `style.transform` writes, about 70 short strings and about 25 small objects (M2).
- Zoom, pinch zoom: `transform` every frame, plus `font-size` whenever a name crosses a half pixel (`nameZoomK` moves a 20 px name through about 7 steps across the names band). Each step is a layout of one contained box and a full repaint of that name's stroke and nine blurred shadows (the 44 px one included). With 17 names, steps from several names can land on one frame. Also `--h` flips for every name at once when the scale crosses 600 px per world unit (L258): 17 repaints on one zoom frame.
- Slider morph: `--a` changes every frame for every name of the fading stop (up to 17 going out over the first 40%, up to 17 coming in over the last 40%), and `--h` flips for all of them on the first and last morph frame (L261). `--a` is used as `opacity` on `.rn b` (`styles/map.css`, `.rn b { opacity: var(--rn-a-ink) }`), and `b` is not its own layer, so every one of those frames re-rasters each fading name's stroke and shadows inside its `.rn` layer. The morph is already the heaviest moment for the canvas (position upload, gas cross-fade).
None of this was timed (the report says so). Smoothness is the core rule, so this cannot be accepted on reasoning either way.
Fix now (one declaration, pixels identical): add `will-change: opacity` to `.rn b`. `b` then has its own layer, its opacity is a compositor value, and a morph frame repaints nothing. It avoids the side effect of the report's `--rn-a-*` swap (see "Cheaper-version switches"). Then Task 9 must time pan, zoom and morph with names on against names off on mains power and take `NAMES_SCALE_WITH_ZOOM = false` and/or `--rn-shadow-lite` if zoom shows it. Until that timing exists the task should be recorded as "full version unproven", not done.

## The departure (placer instead of `requestRender`)

Sound, with I2 and M4.

- Module-level `placer`: one driver per page, registered in an effect, nulled on unmount. Strict Mode double mount ends registered. Remount: M4.
- Called outside a frame: the closure reads `camera.position`/`zoom` and `get().size` live, so it uses the camera as it stands. If a gesture handler has moved the camera and the frame has not drawn yet, names would be placed one frame early; that needs a toggle press in the same tick as a gesture and corrects on the next frame. Not worth guarding.
- Before the driver mounts: `placeNamesNow()` is false, `requestRender()` is called; if the invalidate bridge is not there yet either, the canvas' own first frame places (the basis starts with `layer: null`).
- Toggle off: React removes the layer; the next drawn frame sees no layer and sets `b.layer = null` (L152-155), so toggle on always places (new layer element, new elements, fresh `Written`). `sticky` offsets are kept, so the same names return to the same spots, as the report measured.
- Theme arrival: I2. Font arrival: I3.
- The 0-frame claim for a press is credible from the code: nothing on the press path calls `requestRender` when a driver exists, and the RegionNames test pins it.

## Cheaper-version switches

- `NAMES_SCALE_WITH_ZOOM` (`RegionNamesDriver.tsx:25`): one line, true. With `false`, zoom writes transforms only.
- `--rn-shadow-lite` (`.rn b { text-shadow: var(--rn-shadow-full) }` to `var(--rn-shadow-lite)`): one line, true. It only matters on frames that repaint (font-size steps, `--h` flips, `--a` today); it does nothing for pan.
- `--rn-a-*` swap: one line, but **not equivalent**, as the report half admits: `.rn` has `transition: opacity .2s`, so with the swap the slider's fade would ease 200 ms behind the slider, and removing that transition also removes the fade-in of a name that gains a spot. Prefer I4's `will-change: opacity` on `.rn b`: one line, no change in look or timing, and it removes the per-frame repaint rather than moving it. Keep the swap documented as a fallback only.
